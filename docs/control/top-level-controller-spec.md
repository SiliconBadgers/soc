# RISC-V controller integration

`top_level_controller` connects an Ibex processor, host-loaded local RAM,
PeakRDL registers, and the Memory, Matrix, and Vector queues. The shared
controller contract is the [top-level control unit specification](https://github.com/SiliconBadgers/rtl/blob/cda317be60eebadc7ff35527190efa7458fc11e4/docs/control/top_level_control_spec.md).
The `controller_rtl` dependency pins the queue implementation from
[RTL #29](https://github.com/SiliconBadgers/rtl/pull/29); its
[queue interface](https://github.com/SiliconBadgers/rtl/blob/0a2cb4cf0d5f81f08346d1f7433d822c9e89f6dd/docs/control/command-scoreboard.md)
describes the parameterized arrays. This dependency has its own pin because
the existing `components/rtl` baseline supplies the older MAC smoke fixture.

## Composition

[`top_level_controller`](../../rtl/top_level_controller.sv) connects the
32-bit AXI4-Lite host transport to
[`controller_system`](../../rtl/controller_system.sv). The system contains
[`riscv_wrapper`](../../rtl/riscv_wrapper.sv), local RAM, and
[`controller_regs`](../../rtl/controller_regs.sv). Firmware uses MMIO loads
and stores to stage commands, commit them atomically, observe progress, and
publish completion after the queues and unit interfaces drain.

## Processor and memory

Ibex is the selected controller core. The wrapper also retains CV32E40P for
comparison regressions. Both use the revisions in
[`dependencies.json`](../../dependencies.json). Ibex enters at `0x80` and uses
separate native instruction and data ports. The initial RAM has 4096 32-bit
words; the host owns it before `START`, and the processor owns it for the
execution epoch. Reset preserves RAM contents.

The controller has one synchronous interface domain. The platform supplies
`clk_i`, synchronizes release of `rst_ni`, and connects unit interfaces in that
domain. The AXI port is suitable for the F2 shell's OCL control path.
`host_irq_o` exposes the level request for the platform interrupt adapter.
F2 shell interrupt delivery, clock crossings, and XPM memory mapping belong
to platform composition. The local implementation uses synchronous inferred RAM.

The unit ports carry an opaque payload plus queue-side dependency state.
`PayloadWidth` must hold the selected unit record; the proposed Matrix record
uses 512 bits. Unit decoders and firmware share the packed-format configuration.
The controller regression uses handshake and milestone models at these ports.

## Register generation

[`regs/controller.rdl`](../../regs/controller.rdl) defines the register map,
write ownership, storage, reset values, and interrupt clear behavior. Separate
host and firmware views keep host reads available during a stalled firmware
commit or finish. Shared status and stored values have one owner and a readable
view on the other port. The wrapper implements access validation, queue
acceptance, retained waits, completion, and fault handling.

The locked `controller` dependency group supplies SystemRDL Compiler,
PeakRDL-regblock, and PeakRDL-CHeader. From the SoC root, regenerate and check
the checked-in 128-bit payload, 16-bit counter configuration:

```sh
uv run --locked --group controller python scripts/generate_controller_regs.py
uv run --locked --group controller python scripts/generate_controller_regs.py --check
```

The output directory `generated/controller/` contains the two register
blocks and packages, access masks, configuration package, C headers, and a
manifest of inputs, tool versions, and file hashes. Edit the RDL or generator
and regenerate these outputs together.

Firmware includes `controller_regs.h` and uses `controller_read32` and
`controller_write32` with the generated byte offsets and field masks. These
helpers issue volatile 32-bit accesses from an aligned register base.
The separate host and firmware structure headers describe packed layouts;
the scalar helpers provide the MMIO access API.

For another hardware configuration, generate a separate directory:

```sh
uv run --locked --group controller python scripts/generate_controller_regs.py \
  --payload-width 512 --counter-width 32 --out build/controller-csr-512
```

Compile exactly one generated configuration with `controller_regs`. Its
`PayloadWidth` and `CounterWidth` parameters must match the generated package.
The regression runner generates the selected configuration before compilation.

## RTL and verification entry points

Fetch the pinned RTL and processor sources from the SoC root:

```sh
uv run --locked python scripts/fetch_dependencies.py
```

The fetcher installs `controller_rtl` at `.deps/controller_rtl` using the
revision in `dependencies.json`. Run the controller checks against that pin:

```sh
make test-controller CONTROLLER_ARGS="--out build/controller-vcs"
make lint-controller CONTROLLER_ARGS="--out build/controller-lint"
```

`--rtl-root /path/to/rtl` selects another checkout with the same queue contract.
The runner checks the default RTL and processor revisions and uses the RTL
checkout's `scripts/vcs.py` with VCS
`Y-2026.03_Full64`, assertions, bounded execution, and failure exit propagation.
Results and logs appear in the requested output directory. Verilator performs
lint and elaboration. [SETUP.md](../../SETUP.md) describes tool setup.

Register tests cover independent host and firmware access, exact decoding,
malformed writes, atomic enqueue, backpressure, counter wrap, retained waits,
interrupt event precedence, faulted dispatch, and reset. The wide configuration
checks all sixteen words of a 512-bit command and 32-bit counter arithmetic.
AXI tests exercise independent write channels and stalled responses. Both cores
execute host-loaded firmware through the complete AXI controller assembly.
Deliberately failing runs check result and scenario enforcement.

The [C firmware fixture](../../firmware/controller/csr_backpressure.c) uses
the generated MMIO helpers, initialized data, BSS, and stack storage. The
runner builds it with the locked Zig toolchain and loads it through AXI into
Ibex's RAM. Its 512-bit command configuration fills a depth-two queue, blocks
on the next commit while host reads continue, and completes after the model
publishes the required milestones and drains its work. To run this case alone:

```sh
make test-controller CONTROLLER_ARGS="--only system_ibex_c --out build/controller-c-vcs"
```

The build uses `llvm-objdump` from LLVM tools on `PATH` to retain disassembly.
The output includes the firmware ELF, load image, disassembly, and a manifest
with tool versions, commands, and input/output hashes.

The controller adapts the queue arrays to the three unit ports. Its fault gate
retains offers already visible to a unit and holds subsequent heads in their
queues. Units continue publishing retained milestones for issued work. The
parent drains or cancels that work and coordinates reset before another
execution epoch.
